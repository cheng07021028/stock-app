## H153.2 新增與修正
1. **H114 日K只讀技術證據**：建立布林帶寬（20根、對照前60根帶寬20分位）、OBV 10日方向／量價未發動線索、Wilder風格 ADX（14）和 +DI/-DI。需同日有效日K與至少85根日K、明確成交量「張」單位；不使用任何未來日K或額外行情 API。布林收斂可能向下，OBV不是集保持股，ADX高不代表看漲。
2. **H153 研究排名接線**：布林+OBV的雙因子可作獨立「未發動待驗」研究線索；兩個指標最多+14研究證據分，避免與其他均線訊號無限制重複加分。單一布林或單一OBV不可自動取得研究名次。原有官方基本面、H109/H126風控不變。
3. **同輪研究母體保護**：`godpick_h1532_scope_repair.py` 只有在掃描簽章一致、較完整診斷池是原資料嚴格超集、無重複代號且重疊行情證據無衝突時，才容許於「研究」中恢復完整母體；不改H145/H126，也不把H113限量120檔冒充全市場。若正式會話未保留完整同輪日K，仍須重新掃描；不能自動推造缺少的行情。
4. **主管報表**：原12張表、四彩色頁籤、H151.2 Excel 視窗 XML 修復均保留。 `01_具名強勢研究` 增加 BB/OBV/ADX/DMI 狀態，`03_五檔研究計畫` 帶出已驗證訊號，`02_研究召回統計` 明示研究母體的恢復或無法恢復原因。
5. **H115基本面資料**：持續只使用官方可溯源的 PIT 已公告帳本；**此版沒有完成真實24～36個月歷史營收或估值自動回補**，也不會把 `READ_OK` 誤當完整。缺官方 EPS/PE、法人、集保必須維持待證，未實際建立新模型、未新增經校準隔日上漲機率。

## 驗證與部署
1. 先和實際 GitHub `main` 做差異比對。**不要用舊 ZIP 覆蓋較新的正式程式**，不可覆寫歷史記錄／使用者設定／Secrets。
2. 將此 ZIP 內檔案依相對路徑合併到專案根目錄。
3. `python tools/h1532_verify_deploy.py --root .`
4. 重新部署後確認 H150 Actions 真正成功、H115 官方財務與 H114 行情時間戳、H140 稽核收據，登入並執行一次**完整**同輪掃描，重新建立主管 Excel。不要用11/06的舊資料宣稱11/09的強勢股。
5. Excel 確認12表、00_H126主管決策維持第2張，01研究榜與03五檔的 H153.2 技術欄，02統計的研究母體實際筆數。以真實資料 T+1/T+5/T+10/T+20 做樣本外比較，不因分數增加宣稱績效提升。

**安全界線**：H109/H113/H123/H124/H126 不修改，研究排名不等於交易授權；受否決股票仍不進入正式五檔研究計畫；官方資料缺漏必須明確揭露。
