StockApp V191-H145.0｜同輪候選復原與主管精簡榜
===========================================
本包是 H143 -> H144.1 -> H145 的必要程式增量，不是整站還原包。

適用基準：H143 及既有 H142 Excel Hotfix 的 Page07 程式。
若線上 GitHub 已更新，請逐檔 Diff 合併，不要整包覆蓋其它新修改。

正式程式：
  pages/7_股神推薦.py               已合併 H144.1 + H145 的第 7 頁
  godpick_h144_scope_challenge.py  H144 掃描漏斗證據查核
  godpick_h144_focus_board.py      H144.1 同口徑 H110 研究排名
  godpick_h145_core_bridge.py      H145 同輪候選與 H97 限量輸入修復

H145 重點：
  1. Excel 原始候選只剩一檔而掃描報告聲稱 1665 檔時，只有 H97
     掃描 run_id 一致、決策快取 signature 一致，且快取檔數與同輪報告
     精確一致，才可以從現有完整決策快取復原研究輸入。
  2. H97 限量至 240 筆時，保留本輪已知的作戰候選 ID，並沿用原
     始列內容、原 H79/H110/H109/H123/H124，不變動交易資格與分數。
  3. 匯出前必須核對候選母體、最終作戰檔數及 H97 Audit 覆蓋。
     若報告有 8 檔，但同輪最終名單只剩 1 檔，絕不冒稱已找回 8 檔。
  4. Excel 仍只有兩張表：00_主管重點觀察榜、00_H126主管決策。
     最多顯示 12 檔優先觀察；分數只採用同輪 H110，不使用 H102 舊榜。
  5. 來源異常/缺少同輪證據時將狀態設為 EXPORT_SCOPE_INCOMPLETE，
     阻止自動 H134 決策封存；本次生成的 Excel 只作局部研究。

正式部署前必做：
  1. 備份 GitHub main、runtime-data 及雲端推薦紀錄。
  2. 四個正式程式相對路徑合併；不要上傳任何舊 JSON/Secrets。
  3. 部署後 07 頁執行同輪新掃描，建立主管 Excel，檢視 H145 狀態。
  4. 若原 8 檔尚缺 7 檔，H145 仍會標母體不完整，須從當輪 H97
     原始 run_id/snapshot 追查，不能讓補股或提高推薦資格掩蓋錯誤。
  5. 驗證只有兩張 Excel 工作表、H126 零授權時不產生買進建議、
     Reboot 後仍能核對已封存的正式推薦資料。
